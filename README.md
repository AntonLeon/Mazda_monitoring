# Mazda CX-5 — монитор чатов

Слушает чаты про Mazda CX-5 от имени вашего Telegram-аккаунта, находит сообщения
потенциальных клиентов («забрал машину», «на таможне», «нужна русификация», «помогите
настроить») и присылает уведомления мастерам со ссылкой на сообщение.

## Что изменилось после проверки

| Было | Стало |
|---|---|
| путь к настройкам зашит: `/root/monitor/.env_monitor` — на любой другой машине `TypeError` | настройки ищутся рядом со скриптом, старый путь поддерживается, ошибки понятные |
| без файла сессии бот висел на «Please enter your phone» | проверка на старте: «сессия не авторизована», понятный текст, никакого запроса телефона |
| ключевые слова подстрокой: 7 уведомлений из 9 фраз, включая продавцов и рекламу | правила с весами, границами слов, отрицаниями и стоп-словами продавцов |
| три «голых» `except:` глотали ошибки | конкретные исключения с логом |
| `except Exception` терял уведомление при лимите Telegram | `FloodWait` — пауза и повтор |
| повторы сообщений дублировались | память об отправленном (файл, TTL 24 ч, до 5000 записей) |
| только `print`, без времени и файла | логирование с таймстампами, `journalctl`, опционально файл |
| уведомления только с личного аккаунта | можно отправлять через бота (`MONITOR_BOT_TOKEN`) — аккаунт только слушает |
| `message.text[:300]` без разметки и обрезки | аккуратный текст со ссылкой, категориями и весом, без markdown |
| нет тестов, README, systemd | `selftest.py` (51 проверка), README, `mazda-monitor.service.example` |

## Установка

```bash
cd /opt/mazda_monitor
python3 -m venv venv
./venv/bin/pip install -r requirements.txt

cp .env_monitor.example .env_monitor && chmod 600 .env_monitor
nano .env_monitor            # MONITOR_API_ID, MONITOR_API_HASH, MONITOR_NOTIFY_USERS

cp mazda_session.session .   # файл сессии вашего аккаунта, права 600
chmod 600 mazda_session.session

./venv/bin/python mazda_monitor.py --check     # настройки, сессия, доступность чатов
./venv/bin/python mazda_monitor.py             # запуск
```

Как служба:

```bash
sudo cp mazda-monitor.service.example /etc/systemd/system/mazda-monitor.service
sudo nano /etc/systemd/system/mazda-monitor.service   # путь и User
sudo systemctl daemon-reload && sudo systemctl enable --now mazda-monitor
journalctl -u mazda-monitor -f
```

`MONITOR_API_ID` и `MONITOR_API_HASH` берутся на [my.telegram.org](https://my.telegram.org)
→ API development tools. В файле сессии они не хранятся, поэтому без них монитор не запустится.

## Настройки (`.env_monitor`)

| Переменная | Обязательна | Смысл |
|---|---|---|
| `MONITOR_API_ID`, `MONITOR_API_HASH` | да (для режима личного аккаунта) | доступы приложения с my.telegram.org |
| `MONITOR_NOTIFY_USERS` | да | кому слать: id или `@юзернейм` через запятую |
| `MONITOR_SESSION` | нет | путь к файлу сессии (по умолчанию `mazda_session` рядом со скриптом) |
| `MONITOR_CHATS` | нет | список чатов (по умолчанию 6 из кода), либо `all` — все группы и каналы аккаунта |
| `MONITOR_CHATS_EXCLUDE` | нет | что не слушать в режиме `all` (свой чат мастеров и т.п.) |
| `MONITOR_TZ` | нет | часовой пояс отчётов и журнала (по умолчанию `Europe/Moscow`) |
| `MONITOR_REPORT_HOUR` | нет | час дневной сводки, 0–23 (по умолчанию 9; `-1` — выключить) |
| `MONITOR_DAILY_LIMIT` | нет | лимит уведомлений в сутки (по умолчанию 0 — без лимита) |
| `MONITOR_LOG_CSV` | нет | журнал кандидатов (по умолчанию `monitor_candidates.csv`) |
| `MONITOR_USER_COOLDOWN_HOURS` | нет | сколько часов не повторять уведомление об одном человеке (по умолчанию 168 = неделя; `0` — сообщать о каждом сообщении) |
| `MONITOR_KNOWN_USERS_FILE` | нет | файлы с теми, кто уже писал боту; по умолчанию берутся `data/bot_users.json`, `contacts.json`, `bookings.json` рядом с ботом |
| `MONITOR_KNOWN_USERS_REFRESH` | нет | как часто перечитывать список известных (минуты, по умолчанию 5) |
| `MONITOR_IGNORE_USERS` | нет | ручные исключения: id или `@юзернеймы` |
| `MONITOR_MIN_SCORE` | нет | порог веса уведомления, по умолчанию 3 (меньше — больше уведомлений) |
| `MONITOR_BOT_TOKEN` | нет | отправлять уведомления через бота, а не с личного аккаунта |
| `MONITOR_HEARTBEAT_MINUTES` | нет | раз в N минут присылать «монитор жив» (0 — выключено) |
| `MONITOR_SEEN_HOURS` | нет | сколько помнить отправленное (по умолчанию 24) |
| `MONITOR_DRY_RUN` | нет | `1` — ничего не отправлять, только писать в лог |
| `MONITOR_LOG_FILE` | нет | файл лога в дополнение к journald |

## Словарь слов и автоматизация

**Словарь в `keywords.json`** (создаётся при первом запуске, правится без кода, подхватывается
на ходу — перезапуск не нужен):

```json
{
  "version": 2,
  "rules": [{"category": "русификация", "weight": 4, "patterns": ["\\b(русификац\\w*|...)\\b"]}],
  "veto":  [{"category": "продажа/реклама", "weight": -99, "patterns": ["..."]}],
  "fuzzy": {"русификация": [4, "русификация"]},
  "fuzzy_ratio": 0.8,
  "replies": {"русификация": "Здравствуйте! Русификация — 35 000 ₽..."}
}
```

- `weight` — важность категории; `-99` в `veto` — не уведомлять никогда;
- `fuzzy` — опечатки («русификацыя», «антекор»);
- `replies` — готовые ответы: они попадают в уведомление, мастер копирует и отправляет.
- при смене `version` старый файл сохраняется как `keywords.json.bak`, а новый создаётся заново.

**Журнал кандидатов** `monitor_candidates.csv` — каждая находка и каждый отсев с причиной
(«отсев: продажа/реклама», «вес 2 < 3», «о нём уже сообщали»). По нему видно, какие слова дают
клиентов, а какие шумят:

```bash
./venv/bin/python mazda_monitor.py --report 7   # сводка за неделю
```

**Дневная сводка** приходит мастерам раз в сутки (`MONITOR_REPORT_HOUR`, по умолчанию 9:00,
`-1` — выключить): найдено, уведомлено, причины отсева, категории, чаты. **Дневной лимит**
`MONITOR_DAILY_LIMIT` (по умолчанию 0 — без лимита) страхует от потока в активных чатах.

**Монитор никогда не пишет в чаты и не отвечает клиентам** — только уведомляет мастеров
(в личку или через бота). Ответ отправляет человек, из своего аккаунта.

## Кого не показываем мастерам

Два фильтра, чтобы уведомления не превращались в шум:

1. **Уже писал боту.** Бот ведёт реестр обращений (`data/bot_users.json`), а монитор читает его
   вместе с `contacts.json` и `bookings.json`. Если автор сообщения там есть — уведомление не уходит:
   человек уже общается с вами, мастерам он не новость. Список перечитывается каждые 5 минут,
   перезапуск не нужен. Ручные исключения — `MONITOR_IGNORE_USERS`.
2. **Об одном человеке — одно уведомление.** Если мастер уже получил уведомление об этом
   человеке, следующие его сообщения молча пропускаются в течение кулдауна
   (`MONITOR_USER_COOLDOWN_HOURS`, по умолчанию неделя). В логе видно: `Пропуск (о нём уже
   сообщали 5 ч назад)`. Это главный фильтр против потока: активный участник чата больше
   не превращается в десять уведомлений.
   Открыть лид заново: `python3 mazda_monitor.py --forget 120317642`.
3. **Повторы сообщений.** Одно и то же сообщение (или тот же текст от того же автора) в течение
   24 часов второй раз не отправляется. Записи о людях живут дольше (кулдаун), тексты — сутки.

В логе видно причину пропуска:

```
Пропуск (уже писал боту): @client_one — Забрал машину, подскажите по русификации
```

## Слушаем все группы аккаунта

```bash
MONITOR_CHATS=all
MONITOR_CHATS_EXCLUDE=@mazda_masters,-1001234567890
```

В этом режиме фильтр по списку чатов не ставится вообще: обработчик смотрит события всех
групп и каналов, где состоит аккаунт, а личные переписки и исключённые чаты пропускает.
Поэтому новая группа начинает отслеживаться **сразу**, без перезапуска монитора.

## Как считаются «клиенты»

Каждое сообщение получает вес по категориям:

| Категория | Вес | Пример |
|---|---|---|
| русификация | 4 | «нужна русификация панели» |
| купил/забрал машину | 3 | «забрал вчера, всё супер» |
| таможня/доставка | 3 | «машина на таможне» |
| скрытые функции | 3 | «как активировать скрытые опции» |
| просьба о помощи | 3 | «помогите настроить Яндекс» |
| новый владелец | 2 | «стал владельцем CX-5» |
| доработки | 2 | «интересует антикор» |
| машина из Китая | 1 | «пригнал из Китая» |
| вопрос о цене | 1 | «сколько стоит» |

Всегда отсекаются (даже при высоком весе): объявления продавцов, реклама и скидки,
вакансии и поиск работы. Отрицания снижают вес: «не купил, передумал» уведомления не даст.
Опечатки распознаются: «русификацыя», «антекор», «лабаратории» (порог похожести 0.80
плюс совпадение первых двух букв — подобран по разбору пар слов).

Уведомление выглядит так:

```
🚗 Потенциальный клиент!

👤 @client
💬 Забрал машину вчера, подскажите по русификации

📍 Mazda CX-5 Китай
🔗 https://t.me/mazdachinacx5/12345
🏷 купил/забрал машину, русификация (вес 7)
```

## Проверки

```bash
python3 selftest.py                  # 51 проверка, офлайн, без сети и без telethon
./venv/bin/python mazda_monitor.py --check    # настройки, сессия, чаты
# --check запускайте при остановленной службе: при работающем мониторе он сам откажется,
# чтобы не открывать вторую сессию тем же аккаунтом (Telegram может отозвать ключ).
MONITOR_DRY_RUN=1 ./venv/bin/python mazda_monitor.py   # посмотреть, что попадает в уведомления
```

## Важное про приватность и правила Telegram

* монитор работает от вашего личного аккаунта и читает сообщения чатов, где вы состоите;
* уведомления содержат текст и автора сообщения — это персональные данные, не пересылайте их
  дальше без необходимости и не храните дольше нужного (152-ФЗ);
* автоматическая рассылка с личного аккаунта может привести к ограничениям — поэтому есть
  отправка через бота (`MONITOR_BOT_TOKEN`), лимиты (`FloodWait`) и память о повторах;
* файл сессии `*.session` — это полный доступ к аккаунту: права `600`, только на сервере,
  в git он не попадает (см. `.gitignore`).
